# Feature and configuration reference

Use the launch profiles for an end-to-end workload. Use the worker directly to select individual stages. A worker starts one native proxy for its logical local rank. The native executable also runs transport and forwarding without Python. [Worker entry point](../python/rdma_proxy_worker.py) · [Launch scripts](../scripts/) · [Native JSON and CLI settings](native-configuration.md)

## Effective configuration

The native loader reads JSON and then applies CLI overrides. The launch scripts place their workload arguments first, site-specific settings next and caller arguments last. The worker parses its own flags and appends derived native settings for rank, device, listen port, weight mode and enabled computation stages. Change topology through torchrun and the worker's device maps. Use the worker flags to change projection geometry. Consult `--dry-run` for the assembled native arguments. Full native validation occurs when the proxy loads its configuration.

| Setting | Single-node launcher | Two-node launchers |
| --- | --- | --- |
| Ranks and payload | 8 local by default, 20,480 tokens × 4,096 BF16 elements per source, 5 iterations | Same on each node |
| Router and network | 128 experts, top-8, seed 1234, 32 tokens/chunk, 8 QPs/peer. Staging and NVLink only. NIC initialization still runs. | Same routing, chunk and QP settings, RDMA between matching local ranks |
| Prepared forwarding | Sequential peers, local/RDMA overlap, 64 chunks per prepared batch, queue depth 16, submit/epilogue with atomic ring and prepared local staging, stream synchronization | Same |
| Forward batch-start synchronization | Enabled | Enabled on node 0, disabled on node 1 |
| Up | SwiGLU, MMA 128 × 128, cluster M 2, swizzle 8, output width 2,048 | Same geometry, output width 512 |
| Down | 128 × 128, cluster M 1, swizzle 1, 74 SM budget, expert waves and barrier, tiled additive output | Same with 70 SM budget |
| Combine and return | Local GPU combine, per-group returns, intra-node combine (4 CTAs), inter-node combine (40 CTAs) on local data | Intra-node combine uses 8 CTAs, reverse RDMA enabled, inter-node combine uses 78 CTAs |
| Verification | NVLink return and both combine checks enabled, projection check off. Unweighted, GPU scatter, before-down reset. | Same, plus RDMA return digest check |

Inspect actual launch arguments on any host, including the profile's JSON file and library path.

```bash
python3 python/rdma_proxy_worker.py --help
TORCHRUN_BIN=echo bash scripts/run_single_node_torchrun.sh
TORCHRUN_BIN=echo bash scripts/run_node0_torchrun.sh
```

The first command lists Python worker options. The launcher previews show the arguments passed to that worker. Look up forwarded options such as `--num_tokens=…` by their JSON key in the [native configuration reference](native-configuration.md). For a flag-by-flag interpretation of a complete set of overrides, see the [single-node example](#reading-a-single-node-command).

| --- | --- |

| `RDMA_PROXY_CONFIG`, `TORCHRUN_BIN` | Override the profile's `config/{single_node,node0,node1}_config.json` and torchrun executable. Single-node requires a configuration with no peers. |

## Routing, forwarding and readiness

Native router mode supports 2–8 GPUs per node, 1–1024 experts, and top-k from 1 to the global expert count. The expert count must divide evenly across all GPUs and `num_tokens * top_k` must fit in int32. The raw CUDA entry points generate per-source assignments, per-expert offsets and indices, node token lists (x3) and per-token destination GPU masks (x4). Matching-local-rank traffic uses the full node list. Forwarded input retains only rows selected by the destination's bit. The CuTe implementation and standalone benchmarks provide independent paths for validating routing. [Metadata implementations and CLI](../metadata/README.md) · [Native route construction](../native/src/router_routing.cpp)

| Control | Effect |
| --- | --- |
| `nvlink_forward_preparation_enabled`, `nvlink_forward_submit_epilogue_enabled`, `nvlink_forward_prepared_atomic_ring_enabled` | The native defaults disable preparation. Prepared mode uses bounded queues of copy descriptions. Submit/epilogue separates stream submission from ordered completion handling. Optional `stream_query` completion and the atomic ring require the compatible submission path. The launchers use `stream_sync`. |
| `nvlink_forward_ping_pong_enabled`, `nvlink_forward_ping_pong2_enabled` | Optional distinct handoff policies. Legacy ping-pong hands off at a configured copy call. Prepared ping-pong2 alternates A/B lanes with sequenced ownership and requires preparation. Check exclusivity and barrier prerequisites before enabling either over an existing profile. |
| `nvlink_forward_notification_scheduling_mode` | `per_notification` (default) schedules eligible expert M clusters as contiguous readiness advances. `complete_round` aggregates completions across participating local source GPUs for the same iteration, phase, source-node context and batch ordinal. A zero-payload completion or source-exhaustion marker is meaningful. Requires router mode and forwarding completion notifications. |
| `router_local_input_early_ready_enabled` | Off by default. Publish the already staged own-GPU input when the iteration activates. Other inputs still require transfer visibility. Own-source round completion still participates. Requires local staging and notifications. |
| `nvlink_forward_notification_flush_per_entry_enabled`, `nvlink_forward_notification_flag_update_mode` | Coalesced gather publication by default. Per-entry flush changes publication granularity independently of scheduling policy. Descriptor and applicable scatter writes precede ready-prefix publication. The flag uses `stream-write` by native default or `memcpy` in the checked-in launch configurations. |
| `nvlink_forward_notification_flush_only_enabled` | An isolated notification/flush experiment. The configuration rejects complete-round, early-local readiness and per-entry publication with this setting. |
| `nvlink_forward_notification_scheduling_diagnostics` | Off by default. Enables per-iteration scheduler, M-cluster, expert-run, publication and round-delay counters. All local ranks must agree. |
| `nvlink_return_local_batch_sync_enabled` | Off by default. In per-group mode all local producers arrive for a column group, including empty producers. A producer arrives after its down-ready prefix advances and the preceding group's copies finish. The receiver can keep draining forwarding records while waiting. Requires return completion notifications, per-group results and matching local geometry. |

Use identical scheduling and return protocol settings on participants that share notification state. Same-node forward and return batch synchronization have separate settings. Destination return copies visit logical GPUs in order `(local_rank + 1) % N` through `(local_rank + N - 1) % N`. All segments for one destination share that destination's submission. An empty payload can still require a completion marker. [Round and protocol validation](../tests/native/test_forward_round_protocol.cpp) · [Return barrier tests](../tests/native/test_return_batch_sync.cpp)

## Geometry, arithmetic and publication

The worker selects major capability 9 for Hopper and 10 for Blackwell, including SM103. For the non-blockscaled kernels, Blackwell halves the per-CTA M tile for an even cluster M and MMA M of 128 or 256. Descriptor row capacity is that per-CTA M times cluster M. An up tile M of 128 and cluster M of 2 therefore covers 256 rows on SM90 and 128 on SM100. Native table construction and QuACK must agree before buffers are allocated. The projected N tile count must be divisible by the effective swizzle group size. [Geometry tests](../tests/native/test_gemm_geometry.cpp)

GPU scatter preparation decodes the actual streamed descriptors into compact per-source rows and scatter addresses. All N groups use the same M-row mapping. In CPU per-batch mode, scatter metadata for each M batch is uploaded before its gather readiness. Deferred mode retains descriptors and packs and uploads once after final gather publication. Threaded mode moves packing to a dedicated CPU thread and also uploads once. In both single-upload modes down waits for submission for the current iteration, then waits on the publication event on its compute stream. Python retains the aligned device slab and tensors for the lifetime of the native borrower. Keep cancellation, bounded waits and publication ordering intact. [Native scatter tests](../tests/native/test_cpu_scatter.cpp) · [Python ordering tests](../tests/python/test_cpu_scatter_publication.py)

With weights enabled, source initialization normalizes generated positive weights across the original token's entire top-k set, using an FP64 sum and rounding the quotients to FP32. Each immutable source weight is indexed by its position in the corresponding expert list. Down multiplies each logical FP32 accumulator by its weight before result conversion and additive scatter. Intra-node and inter-node combine sum these already weighted results. Empty domains and zero-weight contributions still participate in readiness. The default unweighted path sums expert contributions directly. [Weighted reference tests](../tests/python/test_weighted_projection.py)

Before-down reset clears additive destinations just before down mapping and computation. End-of-iteration reset clears them after return, combine, reader barriers and validation, including the final iteration. Both policies reset readiness for reuse and charge output clearing to pipeline time. Hardware residence matters when a polling combine kernel overlaps down. Changing geometry, budgets or cluster mode requires both numerical tests and a bounded concurrent run. [Worker composition and reuse tests](../tests/python/test_worker_composition.py)

## Reading a single-node command

This example explains a launch with 20,480 tokens per GPU, width 7,168, and a weighted SwiGLU/down pipeline. The defaults below are those of `scripts/run_single_node_torchrun.sh`, including its JSON and worker defaults. That profile already enables SwiGLU, up cluster M=2, additive down stores, per-group NVLink returns and intra-node combine. [Launcher](../scripts/run_single_node_torchrun.sh)

| Workload and data movement | Meaning in this run |
| --- | --- |
| `--num_iterations=3` | Run three measured iterations (launcher default 5). |
| `--num_tokens=20480`, `--token_dimension=7168` | Each source GPU supplies 20,480 tokens, the launcher default. Each token has 7,168 BF16 elements instead of the default 4,096. Expert assignments can create several routed rows per token. |
| `--nvlink_forward_prepared_batch_chunks=64` | Keep the launcher's 64 chunks per prepared forward batch. At 32 tokens per chunk this covers up to 2,048 input rows. Routing determines how many rows each destination receives. |
| `--router_local_input_early_ready_enabled=true` | Make the GPU's own already-staged input eligible when the iteration starts. Peer inputs still wait for their transfer completions. Default off. |
| `--nvlink_forward_notification_scheduling_mode=complete_round` | Schedule new gather work after collecting the completions for one forward batch ordinal from the participating sources. The default schedules after each data notification. Early-local readiness can publish own-source work ahead of the round. |
| `--nvlink_return_local_batch_sync_enabled=true` | Before submitting a return column group, wait for every local producer to reach that group, including producers with zero rows to send. This setting affects the return path. Default off. |

| Projection and GPU resources | Meaning in this run |
| --- | --- |
| `--grouped-gemm-m-tile=256`, `--grouped-gemm-n-tile=512` | Select the up GEMM's matrix-multiply tile in routed rows (M) and projected columns (N). The launcher uses 128 × 128. On Blackwell with the inherited two-CTA M cluster, a full cluster covers 256 rows, 128 per thread block (CTA). |
| `--grouped-gemm-output-dimension=1536`, `--grouped-gemm-max-swizzle-size=1` | Produce 1,536 features after SwiGLU (launcher default 2,048). SwiGLU requires two projections, so up computes 3,072 columns from 7,168 inputs. Swizzle 1 schedules one 512-column N tile per group, giving six groups per M cluster. The launcher uses swizzle 8. |
| `--down-tile-m=256`, `--down-tile-n=512`, `--down-cluster-m=2`, `--down-max-swizzle-size=2` | Down maps 1,536 features back to 7,168. Use a 256 × 512 MMA tile and cluster two CTAs along M. Group two N tiles at a time. The 14 output tiles become seven 1,024-column ready/return groups. Launcher defaults are 128 × 128, cluster 1, swizzle 1. |
| `--down-bulk-smem-padding=16`, `--down-bulk-smem-cols=128`, `--down-bulk-smem-buffers=1`, `--down-bulk-store-warps=4` | Specialize the **Blackwell** down bulk-store epilogue. Request 16 bytes of shared-memory padding per row, a total budget of 128 buffered columns, one reusable buffer and four issuing epilogue warps. QuACK applies padding when it preserves pipeline depth. The launcher leaves these settings to QuACK. Hopper rejects these explicit overrides. |
| `--down-sm-count=140`, `--intra-node-combine-ctas=6`, `--intra-node-combine-relax-sm-guard` | Set the persistent down kernel's SM budget to 140 and launch six combine CTAs (launcher defaults 74 and 4). The relaxed guard requires at least **146 visible SMs** (140 + 6). The default guard with this geometry requires **152** (140 + 6 × 2). The budget must also be divisible by down cluster M. The guard checks launch headroom. Concurrent progress still needs a hardware test. |

| Contributions, reuse and timeouts | Meaning in this run |
| --- | --- |
| `--weighted-contributions` | Multiply each expert's FP32 down contribution by its normalized routing weight before output conversion and additive scatter. Later combine stages sum those weighted partials. The launcher uses unit weights by default. |
| `--cpu-scatter-preparation`, `--cpu-scatter-publication=threaded` | Move scatter-address and weight packing to a native CPU thread. It processes committed gather-table prefixes as forwarding proceeds. After the final gather publication and packing, one upload transfers the packed metadata. Down waits on that iteration's upload event. Default preparation runs on the GPU. Enabling CPU preparation alone selects `deferred`. |
| `--down-output-reset=end-of-iteration` | Clear additive down outputs after all returns, combines and enabled checks finish reading them, including on the last iteration. The default clears them before down GEMM. |
| `--completion_timeout_ms=600000`, `--return-token-timeout=600` | Both values are ten minutes. The native proxy uses **milliseconds** for progress/completion waits (default 30,000). The worker uses **seconds** for same-node return coordination and CPU scatter event-submission waits (default 120). Each bounds its own waits. |

**Correctness checks.** The launcher checks NVLink return copies, intra-node combine and final token-order combine. The Blackwell quick-start command adds `--check-projections` to compare up and down results against their numerical references on each iteration. [Blackwell test command](development.md#weighted-single-node-test-on-blackwell)

**Running on Hopper.** Use 128 × 128 up and down tiles, down cluster M=1 and a down SM budget of 74 for the single-node example. Keep the launcher's additive `bulk_rows_reduce` epilogue and omit the four Blackwell tuning overrides. The launcher enables the wave barrier, so the worker selects the SM90 ping-pong kernel automatically. That kernel rejects the 256 × 512 down tile.
